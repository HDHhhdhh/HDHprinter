# 빠른 인쇄기 개발 기록

작성일: 2026-10-10. 소스 확인 기준: `38721e7`.

빠른 인쇄기는 반복되는 인쇄 준비를 줄이고, 사람이 정한 순서대로 자료를 출력하기 위해 시작했습니다. 기능이 늘면서 중요한 기준도 분명해졌습니다. **빠르게 요청하되, 이미 보낸 작업을 다시 보내지 않고, 실제 프린터가 끝났는지 알 수 있어야 합니다.**

이 문서는 지난 세션을 다시 읽고 현재 코드·테스트·장애 보고서와 대조한 개발 기록입니다. 새 개발자가 기능 목록뿐 아니라 그 기능이 필요한 이유와 다시 만들면 안 되는 오류를 이해하도록 작성했습니다.

## 현재 동작을 확인하는 순서

이 개발 기록은 과거의 판단을 설명합니다. 현재 기능의 기준은 [제품 동작 정본](../../빠른인쇄기_제품동작_정본.md)입니다. 설치는 [저장소 README](../../README.md), 사용법은 [운영 안내](../../unit_print_manager_README.md), 수정할 코드의 위치는 [AGENTS.md](../../AGENTS.md)를 먼저 확인합니다.

과거 계획에는 취소되거나 수정된 내용이 있습니다. 특히 큐 블록의 `묶기`를 PDF 병합으로 해석한 구현, Aurora 테마, 블록 PDF 제작 제안은 현재 동작의 근거로 사용하면 안 됩니다. 현재 `묶기`는 원본 파일을 반복 순서로 보내는 기능입니다.

## 기록을 읽을 때 주의할 점

- `전송 성공`, `Windows 큐가 비었음`, `Canon 작업 완료 확인`, `사람이 출력물을 확인함`은 서로 다른 증거입니다.
- 검사 개수와 실행 시간은 각 날짜의 결과입니다. 이번 문서 작성에서 애플리케이션 회귀 검사나 실물 인쇄를 다시 수행한 결과가 아닙니다.
- 당시 운영 파일은 복구했지만, 삭제된 과거 Git 객체 전체를 복구한 것은 아닙니다.
- 예측 시간 개선의 재계산 결과는 유효한 설명 자료입니다. 앞으로 모든 인쇄의 오차가 작다는 보장은 아닙니다.
- 공개 문서에는 학생 정보, 실제 주문 내용, 인증값, 원본 세션 덤프, PC별 설정과 실행 이력을 넣지 않았습니다. 과거 보고서의 로컬 경로나 배포 링크는 당시 기록으로만 읽습니다.

기능을 수정할 때는 먼저 해당 오류 사례를 읽고, 연결된 현재 테스트를 확인합니다. 구현 방식은 개선할 수 있지만 사용자가 정한 인쇄 순서, 묶음의 의미, 복구의 안전 기준은 유지해야 합니다.

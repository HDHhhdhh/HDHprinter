# 빠른 인쇄기 검토 및 리팩토링

2026-09-30. 현재 소스와 작업 전 백업을 비교해 실제 호출 경로, 큐 상태, 오류 시 재시도 경계, 화면 갱신 비용을 검토했다. 기존 화면 배치와 단축키를 유지하며 다음 수정을 반영했다.

## 이번에 제거한 비효율

| 문제 | 수정 | 확인 근거 |
|---|---|---|
| 활성 UI와 별도로 남아 있던 이전 UI 및 전용 빌더·그리기 함수 | 호출되지 않는 구현을 삭제하고 `build_ui_reset()` 유지 | 호출 검색, 소스 비교, 전체 회귀 검사 |
| 실제로 사용하지 않는 Canon 직렬 인쇄 경로와 전용 상태 타입 | rolling 인쇄 경로를 유지하고 미사용 경로·대기 함수·`DispatchCheckpoint/Phase` 제거 | 실제 `print_blocks()` 경로에 모의 장비 검사를 추가 |
| 선택만 바뀌어도 큐 전체 이력·파일 합계 재계산 | `refresh_queue_selection()`과 모델 변경용 `update_queue_view()` 분리 | 1,000개 블록에서 100회 선택: 이력·파일 수 조회·합계 문구 쓰기 모두 0회 |
| 큐 전체를 매번 Tk Canvas에 생성 | `unit_print_queue_render.py`에 가시 영역 계산을 분리하고 보이는 행만 생성 | 500행·280px 뷰: 위쪽에서 500→4행, 스크롤한 뷰에서 5행 생성 |
| 클릭·드롭 위치를 큐 전체 순회로 계산 | 일정한 행 높이·간격으로 O(1) 계산 | 기존 경계값과 비교, 100만 행 가짜 큐에서 행 접근 없이 판정 |
| 완료 판정마다 블록별 전체 작업 재검색 | 작업 ID를 블록별로 한 번 그룹화 | 한 블록의 모든 문서가 실제 완료되어야 블록 완료; 다른 블록은 별도 판정 |
| PDF 묶기를 Tk 스레드에서 동기 처리 | 기존 백그라운드 PDF 서비스와 순서 보장 큐 재사용 | 준비 중 큐 수정·삭제·순서 변경, 실패, 취소, 늦은 완료 검사 |
| 같은 동작을 수행하던 드래그 if/else | 중복 분기 삭제 | 기존 드래그 회귀 검사 |

이전 UI·직렬 경로처럼 사용되지 않는 중복 코드, 실제 실행을 검증하지 않는 별도 상태 타입, 선택마다 수행하던 전 큐 작업을 이번의 “AI slop” 정리 대상으로 삼았다. 이름이나 주석이 길다는 이유만으로 정상 기능을 삭제하지 않았다. 카탈로그, 실물 완료 추적, 필수 이력, dry-run, Windows 대기열 fallback은 유지했다.

행 생성·조회 횟수는 합성 환경에서 검증한 계산량이다. 실제 인쇄 시간이나 앱 실행 시간이 해당 비율만큼 빨라졌다고 해석하지 않는다. 미사용 코드 삭제의 직접 효과는 유지보수 범위와 소스 크기 감소다.

## 오류를 줄인 변경

1. **미확정 전송의 자동 중복 인쇄 방지.** Sumatra 호출 경계를 넘은 뒤 결과가 불확실하면, 이력 기록 전에 해당 작업을 재시도 범위에서 제외한다. 확정 전송과 미확정 수를 구분한다. 전송 전 필수 이력 저장 실패는 아직 보내지 않은 작업을 보존한다. 실제 전송 확인 뒤 이력 저장이 실패해도 그 문서를 다시 넣지 않는다.
2. **묶기에서 실제 프린터 대상 비교.** 자동 감지의 `None`을 비교에서 빼던 오류를 수정했다. 자동 감지와 지정 프린터가 같은 대상이면 허용하고, 다른 대상이면 PDF를 병합하기 전에 거부한다. 파일별 지정 프린터도 검사한다.
3. **비동기 묶기의 오래된 결과 차단.** 작업 시작 시 블록 메타데이터와 파일 목록을 복사한다. UI 반영 전에 객체·입력값·위치·상태·프린터를 재검사한다. 되돌리기·전체 비우기·종료로 취소한 결과는 적용하지 않는다. 묶기 준비 중에는 새 인쇄와 재시도 시작을 보류해 확인창의 중첩 이벤트 처리로 원본 블록이 바뀌는 경합을 막는다.
4. **묶음 종류 보존.** `queue_bundle`을 직렬화 왕복 시 유지한다. 한 PDF·1쪽 배치·묶음 조건이 맞지 않는 저장 데이터는 거부한다. 앱 시작 시 큐 자동 복원을 추가한 것은 아니다.
5. **미리보기 검사 무한 대기 방지.** PDF 검사, signature 준비, 스레드 시작에서 예상 밖 예외가 나도 완료 상태를 전달해 active/poll 상태를 해제한다. 같은 실패를 즉시 무한 재시도하지 않으며 다음 명시적 요청은 다시 검사할 수 있다. 실제 인쇄 전 필수 검사는 유지한다.
6. **인쇄 종료 처리 통일.** 완료·중단·실패의 공통 실행 상태 초기화를 한 메서드로 모았다. PDF 준비 서비스 종료가 실패해도 실행 상태는 해제한다.
7. **이력 스냅샷 보강.** 시작·끝 범위, 페이지 배치, 지정 프린터, 문서 종류, 표시 제목을 추가해 같은 식별자의 설정 변경도 이력에서 구분한다.

독립 검토에서 가상화 후 화면 도형의 `bbox`를 전체 큐 높이로 사용하는 회귀를 발견했다. 전체 큐 높이를 공유 계산하도록 수정했고 Down·PageDown·End·Home·반복 이동을 검사했다. 드래그·애니메이션은 실제 이동 좌표와 그림자 영역으로 가시성을 판정한다.

## 검증과 한계

- 작업 전 전체 회귀 검사: 531개 통과.
- 최종 전체 회귀 검사: **586개 통과, 실패·오류·skip 0개**.
- 실제 `print_blocks → rolling` 경로를 모의 장비로 실행해 접수 순서, 정확한 토큰 완료, 불확실 전송, 접수 시간 초과, 전후 이력 저장 실패, 장비 오류·명시적 재개, 다중 파일 블록 완료를 검사했다.
- 운영 환경 의존성 검사 통과. 서버 연동 검사에서 등록 테스트 1,543개, 자료 ID 중복 0개, 누락 PDF 0개. 신규 일산 서버 ID 전체 변환 확인.
- 앱 모듈과 배포 빌더 37개 컴파일 통과. 배포 `APP_FILES` 77개가 존재하며 신규 큐 렌더링 모듈 포함.
- 기존 실행 중 앱, 로그인, 드라이버 설정, 실제 프린터 전송은 조작하지 않았다. 실제 GUI의 시각 상태와 실물 처리 속도는 이번 검증에 포함하지 않았다.

백업·검사 로그·현재 파일 해시·소스 비교는 `output/unit_print_manager/refactor_20260930/`에 보관한다. README와 제품 동작 정본, AGENTS, 배포 파일 수집 목록을 갱신했다. 새 Drive 배포본 업로드는 이번 요청에 포함하지 않았다.

## 다음 개선 제안

| 우선순위 | 기능·구조 | 구현 방향과 이점 |
|---|---|---|
| 높음 | 작업 큐 저장·수동 복구 | 이름·범위·부수·자료 경로를 원자적 스냅샷으로 저장한다. 오류 종료 뒤 사용자가 불러올 때 전송·미확정 항목을 별도 확인하고 자동 출력하지 않는다. 이력과 재시도 상태를 복구 큐로 오인하지 않는다. 등록해 둔 주문을 잃는 문제에 직접 도움이 된다. |
| 높음 | 프린터 프로필과 물리 장비 연결 검사 | 기본·세로·가로·A:ble 큐의 포트/장비 주소를 Canon 모니터 주소와 비교한다. 다른 장비에 보낸 작업을 현재 Canon에서 계속 기다리는 오류를 예방한다. 사용자 지정 프린터는 검사 실패 이유를 표시하고 완료 추적 모드를 명시한다. |
| 중간 | 미확정 전송 확인 화면 | 해당 실행의 토큰·접수·장비 완료·미전송만 모아 보여준다. 사용자 확인 후 필요한 문서만 새 블록으로 추가한다. “재시도하면 중복되는가” 판단을 쉽게 한다. |
| 중간 | 전송 사본과 감사 해시 일치 | 실제 전송용 사본의 바이트와 signature에 감사 기록을 묶는다. 사본 생성 뒤 원본이 바뀌어도 인쇄 내용과 이력이 어긋나지 않게 한다. 사본 검증 완료 전 전송 금지, 조판/복사/해시를 한 준비 결과로 취급한다. |
| 중간 | 인쇄 상태·큐 조작 단계별 모듈 분리 | `PrintManagerApp`는 여전히 약 15,000행이다. 먼저 `PrintBlock/PrintJob/PrintRunOptions`와 실제 프린터 라우팅을 독립 도메인으로 옮기고, 다음으로 실행·hold·미확정 상태 전이를 한 컨트롤러로 옮긴다. UI는 이벤트와 표시만 연결한다. 각 단계는 실제 worker 검사를 유지하며 한 번에 거대한 프레임워크로 바꾸지 않는다. |
| 낮음 | 화면 로그 상한·명확한 미리보기 실패 문구 | 화면 Text는 최근 일정 행만 유지하고 영구 JSONL은 그대로 보존한다. 미리보기 실패 행에는 “확인 실패 · 로그 확인”을 표시해 “확인 중”으로 오해하지 않게 한다. |

다음 작업은 **작업 큐 수동 복구와 물리 프린터 연결 검증**을 먼저 권장한다. 큰 모듈 분리는 이 두 기능의 상태 경계를 고정한 뒤 작은 단계로 진행하는 편이 회귀 위험을 낮춘다.
